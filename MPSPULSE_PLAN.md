# mpspulse Build Plan

## Context

Repo `/Users/enesdemir/Documents/mpspulse` contains only `plan.md` (7 KB, read this session): NVIDIA TensorRT-LLM perf skills ported to macOS Apple Silicon PyTorch MPS, producing measured training-loop profiling and training ETA, exposed as a Python CLI plus Agent Skills-compatible skills with OMP slash commands. End state: git repo with uv-managed Python project, tags `v0.1`–`v0.4` matching plan.md §4, ruff + unit + smoke + MPS integration tests green, and mock-experiment validation run through real OMP commands proving the scenario works. Stack decision: Python + uv (torch is Python-first; TypeScript would need a Python subprocess for every measurement, pure overhead). Branch strategy: `main` + short-lived `feat/*` branches merged with `--no-ff`, one annotated tag per version.

### Step 2 — v0.1 core: MPS timing library + `profile` CLI + skill + OMP command (branch `feat/v0.1-profiling`, tag `v0.1`)

- New module `src/mpspulse/timing.py`: `benchmark_fn(fn, *, warmup=50, iters=100, device="mps") -> dict` using pre-allocated `torch.mps.event.Event(enable_timing=True)` pairs, single `torch.mps.synchronize()` at end (port of NVIDIA `benchmark_detailed`); returns `mean_ms/median_ms/std_ms/min_ms/max_ms/n`. Empty iters (`iters<1`) → `ValueError`. MPS unavailable → raise `MpsUnavailableError` (new exception in `src/mpspulse/errors.py`) with message naming `torch.backends.mps.is_available()`; CLI catches → exit code 2, stderr message. Never fall back to CPU silently (would corrupt GPU/wall separation).
- New module `src/mpspulse/loop.py`: `profile_loop(dataloader, step_fn, *, warmup=5, iters=30) -> LoopReport` dataclass; manual `torch.mps.synchronize()` + `time.perf_counter()` per NVIDIA injection template; per-iter wall ms, data-load ms between iters, samples/sec from `batch_size` arg; sub-phase breakdown via optional `phases: dict[str, Callable]` each wrapped in sync+perf_counter (one-off diagnosis path from NVIDIA "Limitations"). JSON schema in `src/mpspulse/schema.py` as typed dicts: top-level keys `tool/mpspulse`, `version`, `device`, `gpu_event_ms` (nullable), `wall_ms` (always present), `data_ms`, `samples_per_sec`, `memory/{current_allocated,driver_allocated,recommended_max}` via `torch.mps` memory APIs, `warnings[]`. GPU event time vs wall-clock MUST be separate keys; CLI `--explain` prints one line stating which is which.
- `src/mpspulse/cli.py` (argparse, no new deps): `mpspulse profile --model {resnet50,vit_b16,unet_tiny} --batch-size N --iters N --warmup N --json out.json [--explain]`; models resolved from `src/mpspulse/models.py` (torchvision-free minimal CNN/ViT/UNet definitions hand-written to avoid torchvision dep weight — torchvision CPU wheels pull extra ~200 MB; hand-rolled ~150 lines keeps install lean). `--model script:fn` extension: `module:function` import path for user's own `train_step`; subprocess isolation: `--isolated` flag runs the benchmark in `sys.executable -c` subprocess so model/optimizer/checkpoint state in the caller's process is untouched (default ON for `script:` targets, OFF for builtins).
- Skill `skills/mps-profile/SKILL.md` (frontmatter `name: mps-profile`, `description:` required for OMP native discovery): MPS port of workload-profiling workflow — warmup, steady-state, GPU-vs-wall separation, JSON-first, "measure don't guess"; references CLI commands, never raw python timing snippets as source of truth. OMP command `commands/profile.md` (frontmatter `description:`, `argument-hint: "<model> [batch-size] [iters]"`): expands to running `uv run mpspulse profile ...` in repo and summarizing JSON; include `$ARGUMENTS` passthrough. Copy frontmatter shape from `~/.omp/agent/commands/commit.md` (read this session); avoid inventing new frontmatter keys.
- Tests (all in `tests/`): `test_stats.py` (pure unit, no torch: median/std/min/max on synthetic samples; JSON schema keys present); `test_cli_smoke.py` (`--help` exit 0, unknown model exit 2, schema validation of `--dry-run` JSON emitted without torch — implement `--dry-run` emitting schema-shaped fixture); MPS-gated `test_mps_timing.py` marked `@pytest.mark.mps`, skipped if `torch` missing or `not torch.backends.mps.is_available()`: event-vs-wall sanity (gpu_event_ms ≤ wall_ms on a matmul workload), repeatability (two runs CV < 15%), memory keys nonzero. Rationale for `--dry-run`: keeps default `pytest -q` green without torch while still smoke-testing CLI wiring.
- Docs: `README.md` (install via `uv sync --extra mps`, quickstart, GPU-vs-wall explanation), `CHANGELOG.md` entry `## v0.1`.
- Verify: `uv run ruff check . && uv run ruff format --check . && uv run pytest -q` (no-mps green) then `uv sync --extra mps && uv run pytest -q -m mps` on M2 Pro. Merge `--no-ff`, tag annotated `v0.1` with message summarizing done-criteria from plan.md §4.

### Step 4 — v0.2 ETA engine + `/train-estimate` (branch `feat/v0.2-eta`, tag `v0.2`)

- New module `src/mpspulse/eta.py`: `estimate(total_steps, step_ms_samples, *, startup_s=0.0, val_overhead_per_epoch_s=0.0, ckpt_overhead_per_epoch_s=0.0, grad_accum=1) -> EtaReport` returning `{p50_s, p10_s, p90_s, n_samples, source: static|benchmark|live, warnings[]}`; interval from sample quantiles (no scipy: `statistics.quantiles`), never a single number. `static` mode: caller-supplied step time + `low-confidence` warning; `benchmark` mode: runs `benchmark_fn` on representative step then scales; `live` mode: `EtaTracker.update(step_ms)` consuming real step times, ETA recomputed incrementally. Calibration store: `~/.mpspulse/history.jsonl` append of `{model_id, config_hash, step_ms_p50, n}`; `benchmark` consults history for same `config_hash` and warns on >30% drift. Empty samples → `ValueError("need ≥1 step sample")`; `total_steps<1` → `ValueError`.
- CLI: `mpspulse estimate --steps N --epochs E [--mode static|benchmark|live] [--step-ms X | --model ...] [--grad-accum K] [--json]`; `live` reads step times from stdin lines (one float per line) so any training loop can pipe times in. Skill `skills/mps-estimate/SKILL.md` + OMP command `commands/train-estimate.md` (`argument-hint: "<steps> [--mode benchmark]"`).
- Tests: `test_eta.py` pure unit — interval math on fixtures, mode labels, empty-input errors, history drift warning (tmp `HOME` via monkeypatch); MPS test: `benchmark` mode on tiny model produces `source=benchmark`, `n_samples>0`, and `p10<=p50<=p90`. Accuracy check script `scripts/eta_accuracy.py`: profiles mock model, predicts 200-step run, actually runs 200 steps, asserts actual within [p10,p90] and records error % into `examples/mock_experiments/ETA_RESULTS.md`.
- CHANGELOG `## v0.2`. Verify: full suite + accuracy script. Merge `--no-ff`, tag `v0.2`.

### Step 5 — v0.3 performance analysis (branch `feat/v0.3-analysis`, tag `v0.3`)

- New module `src/mpspulse/analyze.py`: `classify(report: LoopReport) -> list[Finding]` with rules operating ONLY on measured fields: `data_ms/wall_ms > 0.2` → `data-loading` bottleneck; `gpu_event_ms/wall_ms < 0.5` with low data ratio → `host-overhead`; memory `driver_allocated/recommended_max > 0.85` → `memory-pressure`; high wall variance (CV>25%) → `variance/thermal-shape` suspect with "re-run, check input shapes" note. Each Finding: `{class, evidence: {metric, value, threshold}, recommendation, priority}`. No NVIDIA specialist delegation — single-machine local analysis; no MFU/SOL (no Apple peak-FLOP API available; do NOT invent peak numbers — state omission in skill).
- Escalation path: CLI `mpspulse analyze --input profile.json [--deep]`; `--deep` runs `torch.mps.profiler.profile()` context around 5 steps and, if `metalperftrace` exists on PATH, captures `metalperftrace` sample during run; missing tools → warning, base report still emitted (plan.md §3 compat rule). `metalperftrace` CLI flags: `unverified — confirm first` via `man metalperftrace` at implementation time; implement with `--help`-discovered flags only.
- Skill `skills/mps-analyze/SKILL.md` (Summary/Metrics/Findings/Recommendations report format ported from perf-analysis) + OMP command `commands/analyze-perf.md`.
- Tests: `test_analyze.py` pure unit over fixture JSONs (one per bottleneck class + clean bill), asserting class + evidence fields; CLI test that `--deep` without tools exits 0 with warning. CHANGELOG `## v0.3`. Merge `--no-ff`, tag `v0.3`.

### Step 6 — v0.4 sync scan + optional gpucapture/gpudebug (branch `feat/v0.4-sync-trace`, tag `v0.4`)

- New module `src/mpspulse/syncscan.py`: AST-based static scan (`ast` stdlib) of a target file for `.item()`, `.cpu()`, `.numpy()`, `bool(tensor)`, `float(tensor)`, `torch.tensor(...cuda/mps...)` in/near loop nodes; output `{file, line, pattern, in_hot_loop: bool, suggestion}` using NVIDIA quick-reference mappings translated to MPS (`.to('mps', non_blocking=True)` etc.). Read-only: never rewrites code (plan.md §4 explicit). CLI `mpspulse sync-scan path/to/train.py [--json]`.
- Optional trace: `mpspulse gputrace -- cmd...` wrapper that (a) checks `which gpucapture`/`gpudebug` (both present on this machine per discovery) and macOS ≥27, (b) launches cmd with `MTL_CAPTURE_ENABLED=1`, (c) runs `gpucapture start --until-exit` per `man gpucapture` (read this session; exact flags `unverified — confirm first` against man page at implementation), (d) optionally runs scripted non-interactive `gpudebug -q` browse commands over the `.gputrace` and attaches summary. Deep profiling is opt-in only; normal `profile`/`estimate` paths MUST NOT set capture env vars (no overhead contamination). Graphics-oriented trace metrics applied to ML compute → always labeled `experimental` in output.
- Skill `skills/mps-sync-trace/SKILL.md` + extend `commands/analyze-perf.md` with `--deep-trace` passthrough (no new command file; one behavior, one entrypoint).
- Tests: `test_syncscan.py` pure unit on fixture files (`tests/fixtures/syncy.py`, `clean.py`) asserting detections + line numbers; CLI test that `gputrace` with unstaged env exits 2 with clear message when binaries missing (monkeypatched PATH). CHANGELOG `## v0.4`. Merge `--no-ff`, tag `v0.4`.
